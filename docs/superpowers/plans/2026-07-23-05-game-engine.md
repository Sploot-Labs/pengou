# Moteur de jeu temps réel — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Faire jouer une partie Kahoot en temps réel : un hôte lance une session à partir d'un quiz, les joueurs rejoignent par code PIN, répondent à des questions chronométrées, et le serveur (autoritaire) calcule les scores, révèle les bonnes réponses, affiche le classement puis le podium — le tout via Socket.IO, sans fuite de la bonne réponse avant le REVEAL.

**Architecture:** Le moteur de jeu vit dans un package pur `@splootlabs/game` (machine à états + orchestration du scoring, **sans dépendance à Socket.IO ni à l'UI**, testable en isolation), au-dessus d'une interface `SessionStore` (impl. mémoire maintenant ; Redis au Plan 7). Le registre `@splootlabs/quiz` est étendu avec `isCorrect`/`score`/`playerView` par type. Le serveur ajoute une **passerelle Socket.IO** qui câble le moteur aux 3 rôles (hôte / grand écran / joueurs), et persiste les résultats (`game_session`/`session_player`/`answer_record`) via `@splootlabs/db` pour les rapports (Plan 6). Joueurs anonymes (PIN + pseudo + join_token).

**Tech Stack:** TypeScript, Socket.IO (déjà attaché au serveur), Drizzle/Postgres, `@splootlabs/quiz`, Vitest + testcontainers + socket.io-client.

## Global Constraints

- **Serveur autoritaire** : le serveur horodate les réponses et calcule les scores. Aucune confiance au timing/verdict client.
- **Anti-triche** : la bonne réponse (et toute donnée permettant de la déduire) n'est JAMAIS envoyée aux clients joueurs avant la phase `reveal`. Les joueurs reçoivent `playerView(payload)`.
- **État autoritatif en mémoire** (SessionStore), résultats persistés en base. L'accès au store passe par une **interface** (impl. mémoire ; Redis plus tard).
- **Moteur pur** : `@splootlabs/game` ne dépend NI de Socket.IO NI de Fastify. Le timing est injecté (`now: () => number`) pour des tests déterministes.
- **Machine à états** : `lobby → question → reveal → scoreboard → (boucle) → podium`. Transitions pilotées par l'hôte ; le passage `question→reveal` peut aussi être déclenché par l'expiration du chrono (serveur) ou quand tous ont répondu.
- **PIN** : 6 chiffres, unique parmi les sessions actives (non `ended`). Joueurs anonymes ; `join_token` pour la reconnexion. Grand écran via **token d'affichage** à usage unique.
- **Scoping tenant** : une session appartient au tenant du quiz/hôte ; la persistance porte `tenant_id` (déjà au schéma).
- ESM/NodeNext, `.js`, TS strict, scope `@splootlabs/*`, Postgres, tests testcontainers + socket.io-client (Docker requis).

- [ ] **Step 1: `scoring.ts` + test**

`packages/quiz/src/scoring.ts`
```ts
// Bonus de rapidité type Kahoot : plein score à t=0, 50% du score à l'expiration.
export function speedBonus(basePoints: number, timeMs: number, maxMs: number): number {
  if (maxMs <= 0) return basePoints
  const frac = Math.max(0, Math.min(1, timeMs / maxMs))
  return Math.round(basePoints * (1 - 0.5 * frac))
}
```
`scoring.test.ts` : t=0 → basePoints ; t=maxMs → round(basePoints*0.5) ; t hors bornes clampé.

- [ ] **Step 2: Étendre `QuestionTypeDef` (types.ts)**
```ts
export interface QuestionTypeDef<P = unknown, A = unknown> {
  key: QuestionType
  validatePayload(raw: unknown): P
  validateAnswer(raw: unknown): A
  playerView(payload: P): unknown
  isCorrect(payload: P, answer: A): boolean
  score(payload: P, answer: A, opts: { timeMs: number; maxMs: number; basePoints: number }): number
}
```

- [ ] **Step 3: Implémenter les 3 méthodes + `validateAnswer` par type** (avec tests `answers.test.ts`)

`mcq.ts` (réponse = index de l'option choisie) :
```ts
import { speedBonus } from './scoring.js'
const answerSchema = z.object({ optionIndex: z.number().int().nonnegative() })
// ...
export const mcq: QuestionTypeDef<McqPayload, { optionIndex: number }> = {
  key: 'mcq',
  validatePayload: (raw) => mcqSchema.parse(raw),
  validateAnswer: (raw) => answerSchema.parse(raw),
  playerView: (p) => ({ options: p.options.map((o) => ({ label: o.label })) }), // pas de `correct`
  isCorrect: (p, a) => p.options[a.optionIndex]?.correct === true,
  score: (p, a, o) => (mcq.isCorrect(p, a) ? speedBonus(o.basePoints, o.timeMs, o.maxMs) : 0),
}
```
`truefalse.ts` (réponse = `{ value: boolean }`) : playerView = `{}` ; isCorrect = `a.value === p.correct`.
`text.ts` (réponse = `{ text: string }`) : playerView = `{}` ; isCorrect = normalise (trim + casse selon `caseSensitive` + accents repliés) et compare à `p.answers`.
`slider.ts` (réponse = `{ value: number }`) : playerView = `{ min, max }` (pas `correct`) ; isCorrect = `|a.value - p.correct| <= tolérance` (tolérance = `max(1, round(0.05*(max-min)))`) ; score = **proximité** : plein si exact, dégressif jusqu'à 0 hors tolérance, puis × bonus rapidité.

- [ ] **Step 4: exports + Vérifier + Commit**

`index.ts` : exporter `speedBonus`, les types de réponse. Ajouter au registre les stratégies étendues (elles le sont en place).
Run: `pnpm --filter @splootlabs/quiz test` → vert (payloads + réponses + scoring). `pnpm --filter @splootlabs/quiz typecheck` → propre.

- Produces : `registerGameGateway(io, deps: { engine; db; auth; config })` — attache les handlers d'événements Socket.IO, câble le moteur (mémoire) + la persistance.

**Contrat d'événements** (room = `session:<id>`) :

- **Joueur** (anonyme) : `player:join { pin, nickname }` → `{ playerId, joinToken }` (+ rejoint la room) ; `player:answer { answer }` (serveur horodate via le moteur) ; `player:reconnect { joinToken }`.

- **Émissions serveur** (par rôle) : `lobby:update { players }` ; `question:show` → aux joueurs `playerQuestionView` (SANS la bonne réponse), au grand écran la question + compteur ; `question:reveal { correct, distribution }` ; `scoreboard { ranking }` ; `podium { top }` ; `timer` (valeur mesurée).
