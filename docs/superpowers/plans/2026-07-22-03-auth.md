# Auth (Better Auth) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajouter l'authentification des hôtes (email/mot de passe + login social Google/Facebook/GitHub, extensible) via **Better Auth**, isolée dans un module identité séparable (`@splootlabs/auth`), branchée sur Fastify et intégrée au multi-tenant existant (`membership`), en gardant la porte ouverte à une promotion future en fournisseur OIDC central « Sploot Labs Accounts ».

**Architecture:** Better Auth gère l'**authentification** (comptes, sessions, social login) avec ses tables (`user/session/account/verification`) définies dans `@splootlabs/db` (adaptateur Drizzle Postgres). Notre schéma **`tenant`/`membership` du Plan 2 reste** et porte l'**autorisation** multi-tenant : on repointe simplement `membership.userId`, `quiz.ownerId`, `gameSession.hostId` vers le `user` de Better Auth. Un package `@splootlabs/auth` isolé configure l'instance Better Auth ; le serveur la monte via `fastify-better-auth`. Les joueurs restent **anonymes** (aucun compte).

**Tech Stack:** Better Auth (`better-auth`, `@better-auth/drizzle-adapter`, `fastify-better-auth`, `@better-auth/cli` en dev), Drizzle/Postgres, Fastify, Vitest + testcontainers.

## Global Constraints

- **Auth = hôtes uniquement.** Les joueurs rejoignent anonymement (inchangé).
- **Better Auth pour l'authentification ; `tenant`/`membership` (Plan 2) pour l'autorisation.** On NE prend PAS le plugin `organization` de Better Auth — on garde notre modèle multi-tenant existant.
- **Tables Better Auth générées par le CLI** (`@better-auth/cli generate`) — source de vérité pour leurs colonnes ; placées dans `@splootlabs/db`. Ne PAS deviner les colonnes à la main : générer.
- **Providers sociaux pilotés par l'env** : un provider est activé si ses `*_CLIENT_ID`/`*_CLIENT_SECRET` sont présents (self-host n'a pas besoin de tous).
- **Secrets** : `BETTER_AUTH_SECRET` (obligatoire hors dev), `BETTER_AUTH_URL` (base URL).
- **ESM/NodeNext**, `.js` sur les imports relatifs, TS strict, scope `@splootlabs/*`, Postgres partout, tests via testcontainers (Docker requis).
- **API Better Auth évolue vite (v1.7+)** : à chaque tâche touchant l'API Better Auth, **vérifier contre la doc courante** (better-auth.com/docs) ; les tâches d'intégration valident empiriquement.
- **Module séparable** : toute la config Better Auth vit dans `@splootlabs/auth` (frontière nette) pour extraction future en service OIDC central.

    baseURL: config.baseURL,
    emailAndPassword: { enabled: true },
    socialProviders: config.socialProviders ?? {},
  })
}

```ts
import type { AppConfig } from '@splootlabs/shared'

export function enabledSocialProviders(
  config: Pick<AppConfig, 'oauth'>,
): Record<string, { clientId: string; clientSecret: string }> {
  const out: Record<string, { clientId: string; clientSecret: string }> = {}
  for (const [name, creds] of Object.entries(config.oauth ?? {})) {
    if (creds?.clientId && creds?.clientSecret) {
      out[name] = { clientId: creds.clientId, clientSecret: creds.clientSecret }
    }
  }
  return out
}
```

import type { FastifyInstance } from 'fastify'
import FastifyBetterAuth, { getAuthDecorator } from 'fastify-better-auth'
import { fromNodeHeaders } from 'better-auth/node'
import type { Auth } from '@splootlabs/auth'

export async function registerAuth(app: FastifyInstance, auth: Auth): Promise<void> {
  await app.register(FastifyBetterAuth, { auth })

  // Route d'exemple protégée : renvoie l'utilisateur courant, ou 401.
  app.get('/api/me', async (request, reply) => {
    const a = getAuthDecorator(app)
    const session = await a.api.getSession({ headers: fromNodeHeaders(request.headers) })
    if (!session?.user) return reply.code(401).send({ error: 'Non authentifié.' })
    return { user: session.user }
  })
}

- [ ] **Step 2: Implémenter `ensureMembership` + `resolveTenantId` (signature élargie)**

Dans `packages/db/src/tenant.ts` :
```ts
import { and } from 'drizzle-orm'

export async function ensureMembership(db: Db, userId: string, tenantId: string, role: 'owner'|'admin'|'member' = 'owner'): Promise<void> {
  await db.insert(schema.membership)
    .values({ userId, tenantId, role })
    .onConflictDoNothing({ target: [schema.membership.userId, schema.membership.tenantId] })
}

export async function resolveTenantId(
  db: Db,
  config: Pick<AppConfig, 'tenancyMode'>,
  opts: { userId?: string; explicitTenantId?: string } = {},
): Promise<string> {
  if (config.tenancyMode === 'single') return ensureDefaultTenant(db)
  const { userId, explicitTenantId } = opts
  if (!explicitTenantId) throw new Error('mode multi : un tenant explicite est requis')
  if (!userId) throw new Error('mode multi : utilisateur requis')
  const [m] = await db.select({ id: schema.membership.id }).from(schema.membership)
    .where(and(eq(schema.membership.userId, userId), eq(schema.membership.tenantId, explicitTenantId))).limit(1)
  if (!m) throw new Error('accès refusé : aucune appartenance à ce tenant')
  return explicitTenantId
}
```
> C'est un **changement de signature** de `resolveTenantId` (Plan 2 : `(db, config, explicitTenantId?)` → maintenant `(db, config, opts)`). Mets à jour les appels existants (le test tenant du Plan 2) et note-le comme rupture d'API intra-projet.
